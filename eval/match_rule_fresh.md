# MATCH RULE (fresh set), version 1, 9 Nov 2026

`eval/match_rule.md` v1 applies unchanged with these substitutions: evaluation episodes = 31–34; G = positive rows of `eval/gold_fresh.csv`; K = 2 × |G|; L = promos fully inside 31–34 in each system's frozen order (v1: `config/eval_order.yaml`; v2: its own frozen v2 order; baseline: frozen round-robin). Scored once; v1 and baseline lists are computed from the existing P07b outputs.

## 1. Why this file exists
- v1 is final and stays the official result (P08). The held-out set was opened at P08, so it cannot test fixes made after seeing it.
- Episodes 31–34 are the fresh set. Their v1 outputs existed before this rule was written and nobody had opened them.
- The gold file `eval/gold_fresh.csv` is hashed in `eval/HASHES.md` and is never committed.

## 2. Fixed before scoring
- Hashed in `eval/HASHES.md`: this file, `eval/gold_fresh.csv`, `config/v2.yaml`, and `config/eval_order_v2.yaml` if the v2 order uses one.
- The L files (v1, v2, baseline; held-out and fresh) are generated by code from stored outputs. Their sha256 values are written to `L_seal.json` at generation and re-checked at scoring. No gold file is read when an L file is made.
- v2 uses `config/eval_order.yaml` unchanged: there is no separate v2 order file (the per-episode diversity cap was not adopted). The needs_human lane is a label only and does not change the order (D66).
- No fresh-episode promo content, span, line ID or score is opened or printed before scoring; counts only.

## 3. Primary and descriptive results
- **Primary:** v2 Recall@K at τ = 0.5 (match rule §5), and the paired v2-vs-v1 contrast on G (a_i = 1 if v2 matched gold i, b_i = 1 if v1 did).
- **Everything else is descriptive:** hook-hit, hook-found, Precision@10, recall by grade, negative-hit rate, v2 vs baseline, and the τ = 0.3 and 0.7 rows.

## 4. Metrics (match rule §5 and §6, unchanged)
- Recall@K, hook-hit, hook-found, Precision@10, recall by grade and negative-hit rate, each with Wilson 95% where the rule gives one.
- Exact two-sided McNemar for v2 vs v1 and for v2 vs baseline. Paired bootstrap of mean(a − b): B = 10,000, seed 12345, percentile 95% interval.
- K = 2 × |G|, about 16 for about 8 positives. Precision@10 is as in §5: matches among ranks 1–10 of L divided by min(10, |L|).
- The baseline sensitivity row (20–60 s check off, §6) is reported as in P08.

## 5. Score once
- One scoring run on the fresh set. The ledger records `scoring_runs = 1`. Any later run is counted and labelled "dev".

## 6. Held-out set after the fact
- v2 on the held-out episodes is reported next to the official v1 numbers and labelled "post-hoc (after seeing v1 results)". It is not a result.

## 7. Statement
- The labeller (Hariom) had read the whole show before labelling the fresh set. Gold reflects one person's editor judgement and is incomplete.
- With about 8 positives and 2 negatives, every result is descriptive. One gold promo moves a recall figure by about 12 points.
